# ChipFinder — правила для Claude Code

Программа для Windows 7: по фото микросхемы находит, скачивает, проверяет и подтверждает datasheet,
даёт заключение о наличии памяти. Архитектура — `docs/ARCHITECTURE.md`. План — `docs/ROADMAP.md`.
Общайся с пользователем по-русски, коротко.

## Машины
- Разработка: **MacBook Pro M4** (macOS, arm64). Python 3.8 через `uv python install 3.8`, окружение `.venv`,
  Tesseract — `brew install tesseract`. Программа и окно должны запускаться и на Mac (как рабочая программа,
  не заглушка) — пользователь тестирует на Mac. Тесты окна — `QT_QPA_PLATFORM=offscreen`.
- Цель: **Windows 7 SP1 x64**, i5-6500, 16 ГБ, встроенная графика, **без прав администратора**.
  Поставка — портативная папка (встроенный Python 3.8.10 + пакеты + Tesseract), собирает CI (шаг 0.6).
  Программа пишет только в свою папку и в библиотеку на сетевом диске. Никаких установщиков, реестра, служб.
- Windows-проверку делает CI на каждый push. Рабочий ПК доступен пользователю раз в день, поэтому проверки на
  Win7 **не останавливают разработку** и делаются пачкой («выезды», `docs/ROADMAP.md`):
  - всё, что нужно узнать с Win7, оформляется как проверка в наборе (`tools/win7_pack/` → `checks/` в сборке),
    а не как просьба «запустите и пришлите»; один запуск `Проверка на работе.bat` → один `отчёт_<дата>.zip`;
  - проверка сама перебирает запасные варианты и собирает полную диагностику, чтобы не понадобился второй выезд;
  - шаг ★ = добавил проверку в набор, CI зелёный → шаг готов, идём дальше; не просить съездить ради одного файла;
  - ручные действия на Win7 — только в `checks/ЧТО СДЕЛАТЬ.txt`, одним списком на выезд.

## Папки пользователя `my_test/` и `my_reports/`
- Только локальные: в `.gitignore`, **никогда** не коммитить, не копировать их содержимое в `tests/fixtures/`,
  не цитировать в коммитах. Проверяй `git status` перед каждым коммитом.
- `my_test/` — реальные фото и PDF для проверки (тесты с меткой `mytest`, пропускаются без папки).
- `my_reports/` — отчёты, логи, скриншоты с рабочего ПК и снимки окна (`my_reports/screens/`). Когда
  пользователь пишет «отчёт в my_reports/…» — прочитай его и предложи исправления шагами.

## Жёсткие ограничения платформы
- Код обязан работать на Python 3.8: никаких `match`, `list[str]`/`dict[...]` в аннотациях без
  `from __future__ import annotations`, `str.removeprefix`, `zip(strict=)`, `X | None`.
  Проверка: `vermin --target=3.8- --no-tips chipfinder`.
- Зависимости только из `requirements.txt` (версии под Win7; для Mac — маркеры `; sys_platform == "darwin"`).
  Новая зависимость — только с wheel для cp38 win_amd64; сообщи пользователю.
- Никаких Windows-only или Mac-only API в коде программы (кроме изолированных мест с проверкой платформы).
- Пути: русские буквы, пробелы, UNC (`\\server\share`). Картинки — через `np.fromfile` + `cv2.imdecode`.
- Сеть — только через `chipfinder/core/netsafe.py`. Не обходить капчу, не отключать проверку сертификатов.
- Ход поиска — только событиями `acquire/events.py` с ключом сообщения; текст на языке поиска (EN/中文/RU)
  из `data/i18n/*.json`. Новый ключ — сразу во все три словаря.
- Неудачи обращения к сайтам классифицируются (`acquire/netdiag.py`, §4.11) и попадают в заключение.
- Каждый поиск пишет статистику (`acquire/stats.py`, §4.10).

## Интерфейс (ARCHITECTURE §5)
- Современный вид: тема из токенов, светлая/тёмная, иконки, аккуратные отступы. Не стандартный «серый Qt».
- Отзывчивость: в потоке интерфейса нет сети, PDF, OCR, обращений к сетевым дискам и долгого SQL.
  Обновления из фона — сигналами, пачками (≤ 30/с). Списки и таблицы — через модели.
- После шага, меняющего окно: `tools/screenshots.py` → `my_reports/screens/`, посмотри снимки сам и исправь
  явные дефекты до коммита.

## Модули и расширения (ARCHITECTURE §6)
- Роли конвейера меняются через `config.json → modules`; интерфейсы — `core/interfaces.py`.
- Новые функции с интерфейсом — как расширения (`chipfinder/extensions/`, `plugins/`) через `extensions/api.py`,
  а не правкой главного окна. Изменение API или интерфейсов — только с записью в раздел «Решения».

## Распознавание (ARCHITECTURE §6.1)
- Каждый способ распознавания — провайдер в `recognition/providers/` или `plugins/ocr_*`; менеджер не знает
  о конкретных провайдерах. Облачный провайдер никогда не вызывается без согласия пользователя.

## Как работать над задачей
1. Прочитай в `docs/ROADMAP.md` только текущий шаг (первый с `[ ]`) и файлы, которые он называет.
   Не читай весь проект — экономь токены.
2. Сначала тест (pytest, `tests/`), потом код. Тесты без интернета: `tests/fakes/fake_http.py` и
   `tests/fixtures/`. Тесты с реальной сетью — `@pytest.mark.live`, только вручную.
3. Перед коммитом всё зелёное: `python -m pytest -q -m "not live"` · `ruff check .` ·
   `vermin --target=3.8- --no-tips chipfinder` · `git status` без my_test/my_reports.
4. Маленький коммит на шаг, сообщение по-русски: `шаг 3.2: адаптер DuckDuckGo + тесты`. `git push`.
   Отметь шаг `[x]` в `docs/ROADMAP.md`, добавь строку в `docs/PROGRESS.md`.
5. Шаг больше ~300 строк изменений — раздели на подшаги и спроси пользователя.
6. В конце ответа ОБЯЗАТЕЛЬНО:
   «✅ Шаг N готов, тесты зелёные, запушено (коммит abc123). Проверить на Mac: … . В набор для Win7 добавлено: … (если добавлено; выезд N).
   Можно очищать чат командой /clear. Следующий шаг: N+1 — <название>, модель: <метка шага из ROADMAP>.»
   Если текущая модель не совпадает с меткой шага — скажи об этом в самом начале, до работы.
   Если тесты не прошли — не коммить, опиши проблему, чат не очищать.

## Нельзя
- Коммитить: `.venv/`, `venv/`, `wheels/`, `my_test/`, `my_reports/`, `data/library/`, `data/quarantine/`,
  `*.sqlite`, `logs/`, `config.json`, архивы, скачанные PDF, API-ключи. Настоящие datasheet в фикстурах — нельзя
  (только сгенерированные PDF и урезанные HTML-страницы).
- Удалять или ослаблять правила безопасности (`docs/ARCHITECTURE.md` §8).
